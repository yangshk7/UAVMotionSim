# 独立运动航段模块接口

## 面向 SAR 的最小产出

普通“运行仿真”默认一段航迹。每段新导出三份文件：`motion_truth_pass1.csv` 为输出航迹原生积分频率的**仿真物理真值**，`motion_navigation_pass1.csv` 为同一时间原点的导航位姿估计，`motion_segment_pass1.json` 记录来源、频率、坐标、时钟关系和样本数量。默认配置是 3200 Hz 真值、100 Hz 导航、20.48 s，含首末两点，分别为 65537 和 2049 点。**20.48 s 只是原验收基准，不是航迹长度上限**；可在上位机设为 100 s，导出完整 100 s 后在 SAR 程序中裁剪。更改积分频率或时长后，JSON 会记录实际配置值。单独的 800 Hz `uav_motion_pass1.csv` 与原 MATLAB 接口继续保留。

两个 CSV 采用相同字段：`time_s`（输出航迹开始为 0，单位 s）、`cg_x_sar_m` 等三轴机体质心位置（m）、`cg_vx_sar_mps` 等三轴速度（m/s）、`qw_nb` 等四个姿态分量（机体 FRD 到局部 NED 的标量在前四元数）、`apc_x_sar_m` 等三轴 SAR 天线相位中心位置（m）。位置和速度的 SAR 坐标是 X 前、Y 右、Z 上。导航文件的位置、速度和姿态为估计量；真值文件不叠加导航估计误差。APC 由各自的位姿与配置中的 FRD 杆臂计算。

命令行 100 s 示例：`uv run --no-sync python -m uavsim.cli run --config configs/route_100s.yaml`。内部配置字段仍叫 `acquisition_duration_s`，但它控制**完整输出航迹时长**；未来 SAR 裁剪不在本模块内执行。轨迹类型默认是持续匀速直线，中心位置随总时长平移，100 s 时从约 X=-500 m 至 X=500 m；扰动默认持续到航迹末端。

上位机默认加载 `main/motion_config.yaml` 并选择 `route_length`。输入目标有效长度 `L`、名义速度 `v`、额外裕量 `M` 后，程序按 `T = L/v + M` 计算完整输出时长，并只向上对齐公共采样网格；默认 `M=10 s`，可在上位机修改。例如 `configs/route_1000m.yaml` 给出 `L=1000 m`、`v=10 m/s`，输出 `110 s`，名义目标区间处于前后各约 5 s 裕量之间。质量检查优先给出连续达标区间中间的裁剪窗。此模式目前只支持持续匀速**直线参考**，不模拟起飞爬升或降落；其他航迹类型可继续使用固定时长模式。`main/config.yaml` 保留原固定时长验收基准。

名义速度不保证受扰动物理真值每一时刻都达标。按长度模式在**原生积分采样点**上检查沿 SAR X 的连续前进距离和速度模长。仅无物理扰动时，`v × (1±10%)` 是匀速航段硬门槛；物理扰动开启后，它只是速度观测统计，不决定仿真是否通过。两种情况的裁剪窗首末点都必须同时落在真值和 100 Hz 导航网格上。容差可在上位机调整，作用于无扰动基准检查。`route_quality` 标明 `assessment_mode`、是否执行速度门槛、速度实际范围、速度带内比例、连续前进距离和可裁剪时间窗。运动状态还需通过有限值、运动学、姿态单位模及时间网格检查。缺少目标长度时明确标记不达标，原始航迹照常保存，不通过删点或修改速度掩盖问题。随机扰动的输出幅度不能仅由输入标准差推定；本阶段用已记录的配置与种子、可复现性和物理一致性验收，统计分布区间需另做多次重复试验。

核心契约是 `uavsim.motion.MotionSegment` 与 `MotionSeries`。`from_simulated_pass(pass_result, config)` 从已有单航次计算结果构造输出航迹，`export_motion_segment` 写文件，`load_motion_segment(directory, "pass1")` 读取并复核。`crop_motion_segment(segment, start_time_s, end_time_s)` 在共有样本时刻同步裁剪真值与导航，并把新航段时间重置为零；不修改源文件。契约检查时间严格递增、采样率与时间轴一致、数组维度、有限值、单位四元数，以及两路覆盖相同的航迹区间。当前只接受 `exact_common_grid`，防止把外部飞控的接收时间近邻配对误标为已完成 SAR 脉冲同步。

上位机现有页面已能独立调节运动扰动、位置/速度/姿态导航误差和随机种子，并保存配置快照。误差标准差是统计尺度，不是最大偏移量；改变导航误差不会修改物理真值。当前导航是独立合成误差模型，不是 GNSS/IMU 融合估计器。

## 外部数据适配边界

两套外部飞控的机体真值与导航现已通过各自原始日志的**共同仿真时钟**对齐：PX4 用 Gazebo 时戳与 ULog `timestamp_sample`，SITL 用 DataFlash `TimeUS` 与 MAVLink `time_boot_ms`，并作独立交叉检查。具体数据、频率及误差见[外部时钟对齐报告](external_clock_alignment.md)。SITL 原 MAVLink `SIMSTATE` 流仍没有自身时戳，但改用 DataFlash `SIM2` 获得约 400 Hz 带时戳位置/速度真值。100 Hz 导航在 PX4 和 SITL 都有明确的插值来源，SITL 真值姿态采样率低于位置/速度。外部 CSV 目前是**同钟机体轨迹**，尚未标定 CG→APC 杆臂和导航共同原点，因此不冒充本模块 `MotionSegment` 的 SAR 就绪 APC 数据。时钟对齐已完成；估计器内部滞后与机体标定是不同问题。

两份原始仿真规范均给出 FRD `[0,0.1,0.2] m` 工程杆臂，上位机可修改，并能为外部同钟机体轨迹另生成 APC 派生 CSV；详见[仿真杆臂说明](lever_arm_simulation.md)。这完成了仿真几何配置与计算验证，但没有目标机型独立 APC 观测，因此不称为实测杆臂标定。

本阶段没有改变两套外部飞控、原 `UAV_Motion_Sim`、物理参数、既有文件格式或 MATLAB SAR 工程。默认单航段只影响普通仿真入口；完整科研验收仍固定双航次。
