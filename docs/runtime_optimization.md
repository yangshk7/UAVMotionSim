# 运行资源与优化

> 版本口径：最终版参数、功能边界与验收结论统一以 [v1.1.0发布说明](FINAL_RELEASE.md) 为准。本文带日期的运行数字是对应历史实验记录，不代表最终版重新测得的结果。

每次命令运行时检测 CPU 逻辑线程、可获得的物理核信息、物理总内存、当前可用内存、GPU 型号和总/空闲显存。NVIDIA 使用 `nvidia-smi`，Windows 使用 GlobalMemoryStatusEx 与可用的 CIM 信息；缺失信息标记 unknown，不编造容量。显存探测不依赖 CUDA、Torch 或 CuPy。

资源规划以当前可用 RAM 为基础，默认最多使用其 60%，同时保留至少 2 GiB。估算包含主进程保留的全部结果、工作进程、预生成输入和跨进程复制。CPU、内存、航次数和用户并行上限共同约束 worker 数；短于 16,000 积分点的自动任务串行以降低进程启动开销。

主动力学为 19 维、时间上有反馈依赖，采用 float64 CPU；多航次使用独立进程。矩阵逆与分配伪逆预计算；状态和日志数组预分配；标量旋转和小向量运算走轻量路径；NumPy/SciPy 线程由 threadpoolctl 限制为每 worker 1 个，避免进程与 BLAS 线程相乘。

所有计算保留原始积分频率和随机输入。不会通过降采样、减少脉冲、改用 float32 或删去电机动态来加速。每个航次记录耗时和操作系统进程峰值 working set；硬件信息和资源决策保存在 metadata.json。

当前 `gpu_used=false`，GPU 仅探测并记录。若后续开展大量 Monte Carlo，应先为批量动力学建立 GPU 内核，并核验 float64、CPU 一致性和吞吐量，再考虑显存分块；这不属于当前已验证后端。安装大型 GPU 依赖前需遵循用户的依赖变更要求。

运行 `uv run --no-sync python scripts/benchmark.py` 可比较相同完整配置的串行/并行耗时和逐位一致性。加速比受机器负载影响，不能保证固定数值。内存规划是保守启动估算，不是对操作系统后续内存变化的硬隔离。
